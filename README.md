# 表情与话术偏好收藏（AstrBot 插件）

主人在 QQ 私聊里说「这张我喜欢」「这个视角我喜欢」「这句我喜欢」时，把对应的图片或原话收藏到本机；之后可以用命令按原图重发、按编号取回，或者让模型在合适的语境里从收藏的表情中挑一张发出来。

插件只对配置里填的那一个 QQ 号、且是 aiocqhttp 适配器下的私聊生效。群聊、其他人的私聊都不会被处理，也不会收到任何回复。

> 插件名 `astrbot_plugin_dafeiyu_favorites` 是历史命名。插件功能与具体人设、昵称无关，可以配给任意 AstrBot 人设和 QQ 号使用。
>
> 本仓库是公开发布版：默认配置为中性空值，不内置任何真实 QQ 号、适配器名、密钥或个人昵称；所有需要绑定的值都由使用者在 AstrBot 后台自行填写。

## 功能特性

- **只服务主人私聊**：每条消息先判断平台是 `aiocqhttp`、会话是私聊、发送者是配置里的 `owner_qq`，并且完整会话标识等于 `适配器ID:FriendMessage:主人QQ`。只要有一条不满足就直接返回，不记录、不回复、不注入。
- **自然语言收藏图片**：主人在私聊里说「这张我喜欢」「这个视角我喜欢」「好喜欢这张图」等正面评价时，按下面几种来源找到那张图并存到本地：同一消息里附带的图片、引用的单张图片、最近 180 秒内主人刚发过的图片、或机器人上一条回复里的图片。
- **自然语言收藏话术**：说「这句我喜欢」「太会说」「说得好」时，把机器人刚才那句话（引用里的原文，或上一条回复文本）存成一条话术收藏，并自动打上语气标签（短句、停顿、口语语气、玩笑感等）。
- **保守的意图判断**：只有文本不超过 60 字、包含正面词、且不含「别 / 不要 / 不想 / 算了 / 如果 / 要是 / 你喜欢吗」等否定、条件、反问词的句子才算收藏意图。判断不了的句子不会保存，也不会打断正常对话。
- **收藏列表**：主人私聊发 `/偏好收藏`，按编号列出最近 8 张收藏表情和最近 5 条收藏话术；每张图如果有备注就显示备注，否则显示分类标签。
- **按编号取原图**：`发收藏图 1` 取回编号 1 的图；`发收藏图 <12 位十六进制 ID>` 用稳定 ID 取回。
- **给收藏起名**：`备注 1 猫猫转圈`、`描述 1 猫猫转圈`、`改名 1 猫猫转圈` 都可以，备注最多 40 字，会显示在列表里。
- **重发刚才那张图**：说「再发刚才那张」「能不能再发一次刚才那张图」「重发上一张」等，插件会把最近 180 秒内确认发送过的那张图重新发一次；也可以直接引用图片再发。
- **把主人发的图原样发回**：主人发一张图后说「你发这张我看看」「把这张图发给我看看」，插件会发回同一张图（也支持引用单张图片再说）。
- **QQ 收藏表情支持**：AstrBot 会把 `mface`（QQ 商城/收藏表情）消息段丢掉，插件从原始事件里自己取 `emoji_id` 并按 QQ 的规则拼出图片地址下载；只有 file id 没有地址的表情，会再调 NapCat 的 `get_image` 找回。
- **让模型学着用**：主人在私聊触发 LLM 时，插件往系统提示词末尾追加收藏的语气标签和候选表情图；模型可以在回复末尾写内部标记 `&&偏好图:真实编号&&` 来选择发一张收藏表情，插件在发送前把标记替换成图片。
- **不主动打扰**：插件没有任何定时任务或主动发送逻辑；所有输出都是对主人当前私聊消息的回应。
- **本地存储、无外部服务**：数据全部存在 AstrBot 插件数据目录；图片下载只允许访问 QQ 的 CDN 域名，不经过自建服务器，不调用任何模型或账号 API。

## 适用场景 / 不适用场景

适合：

- 单主人、以 QQ 私聊为主的 AstrBot 实例，希望机器人记住「主人喜欢哪些表情、哪种说话方式」。
- 想让自己发过的表情包可以在之后随时按原图重发，不用去翻聊天记录。
- 已经安装 `meme_manager` 一类表情包插件，希望把机器人发过的表情也纳入「重发刚才那张」。
- 接受把收藏的图片保存在本机、并且愿意在后台手动填写主人 QQ 和适配器 ID 的用户。

不适合：

- 多用户共享、需要给不同用户分别收藏的场景（插件只认一个主人 QQ）。
- 群聊场景（插件明确只处理私聊）。
- 非 QQ 平台或非 `aiocqhttp` 适配器（代码按 `FriendMessage` 会话结构判断，其他平台未验证）。
- 完全离线、不能访问 QQ 图片 CDN 的环境（QQ 收藏表情的下载会失败）。
- 不想让收藏内容进入模型上下文的环境：为了学习语气和选图，插件会把语气标签、图片标签和编号拼进主人私聊的系统提示词。

## 工作原理

### 一次私聊消息的处理流程

```
主人私聊消息
  │
  ├─ 是 /偏好收藏、发收藏图、备注、再发… 这类直接命令
  │     └─ 立即处理并 event.stop_event()，默认对话和其他插件不再接这条消息
  │
  └─ 其他消息
        ├─ 判断是不是收藏意图（feedback）
        │     ├─ 命中 → 保存图片/话术到本地，并给本轮 LLM 请求加一句真实收藏回执
        │     └─ 未命中 → 什么都不做，消息照常进入正常对话
        │
        └─ （若触发 LLM）
              on_llm_request：追加语气标签、已收藏偏好、候选表情列表
              模型回复：可能在末尾写 &&偏好图:<12位编号>&&
              on_decorating_result：清掉标记，选中编号合法且候选内时把图片追加到回复
              after_message_sent：记录这次真正发出的图，供之后「再发刚才那张」使用
```

### 数据从哪来

1. **图片收藏**来源优先级（同一段代码 `image_data()` 同时用于「收藏」和「取回」）：
   1. 消息组件带本地路径，且路径位于本插件 `images/` 或 `plugin_data/meme_manager/packs/` 之内 → 直接读文件。
   2. 组件带 OneBot/NapCat 给的本地绝对路径（NapCat 自己的图片缓存）→ 直接读文件。
   3. 组件的 `url` 或 `file` 是 `base64://...` → 解码成字节（先按 8 MiB 上限粗查长度）。
   4. 组件带 `https://` 地址 → 走下载器，只允许 QQ CDN 白名单域名。
   5. 只有 file id（QQ 收藏表情常见）→ 调 NapCat 的 `get_image(file=...)`，依次尝试它返回的 `base64`、本地 `file`、`url`。
   6. 全部失败 → 写一条 `[偏好收藏] 读取原图失败` 日志，直接命令会回复「我没能取到那张原图……」。
2. **话术收藏**来源：优先用被引用消息里的纯文本（且引用的是机器人自己）；没有引用时用上一条机器人回复的文本（180 秒内有效）。
3. **QQ 收藏表情**：从原始事件的 `mface` 段取 `url`（必须是 https），没有 `url` 时用 `emoji_id` 拼 `https://gxh.vip.qq.com/club/item/parcel/item/<emoji_id 前两位>/<emoji_id>/raw300.gif`。

### 什么时候处理

- **收到主人私聊消息时**：优先匹配直接命令；不匹配时做一次收藏意图判断；都不命中就完全交给 AstrBot 正常流程。
- **消息发出后**：`after_message_sent` 记录这次回复里唯一确认发送的图片和纯文本，供「再发刚才那张」「这句我喜欢」使用。这些记录只存在内存里，AstrBot 重启后清空。
- **LLM 请求前**：`on_llm_request` 在主人私聊的系统提示词末尾追加偏好内容。
- **回复发送前**：`on_decorating_result` 解析并清除 `&&偏好图:...&&` 标记，决定是否附图。

### 收藏怎么存

收藏数据用 SQLite（`favorites.sqlite3`）加图片目录（`images/`）：

- 图片按内容 SHA-256 去重：文件名是完整 SHA-256 加扩展名，收藏记录里的 ID 是 SHA-256 前 12 位。
- 支持 PNG / JPEG / WEBP / GIF，单张图片 ≤ 8 MiB，宽 × 高 ≤ 20,000,000 像素；不满足的直接拒绝并写日志。
- 图片先写临时文件再原子替换，避免中断留下半张图。
- 话术按「原话」去重，原话最多保留 500 字；语气标签由代码从原话里提取（短句、停顿、口语语气、玩笑感、私聊语气等），用 `|` 连接。
- 备注（`detail`）最多 40 字，只在图片收藏上生效，列表里优先显示备注。

### 数据存在哪

所有数据在 AstrBot 的插件数据目录下（代码通过 `StarTools.get_data_dir("astrbot_plugin_dafeiyu_favorites")` 获取，AstrBot 4.x 通常位于 `<AstrBot 数据目录>/plugin_data/astrbot_plugin_dafeiyu_favorites/`，以实际运行环境为准）：

```
astrbot_plugin_dafeiyu_favorites/
  favorites.sqlite3              # 收藏记录
  images/
    <sha256>.png                 # 收藏的图片，按内容哈希命名
    <sha256>.gif
```

SQLite 表结构（供排查和手动清理参考）：

```sql
CREATE TABLE favorites (
  id TEXT PRIMARY KEY,      -- 图片为 sha256 前 12 位；话术为 "phrase:"+原话 的哈希前 12 位
  kind TEXT NOT NULL,       -- 'image' 或 'phrase'
  title TEXT NOT NULL,      -- 图片为分类标签；话术为原话
  detail TEXT NOT NULL,     -- 图片为备注；话术为 '|' 分隔的语气标签
  file TEXT NOT NULL,       -- 图片在 images/ 下的文件名；话术为空字符串
  created INTEGER NOT NULL  -- 写入时的 unix 时间戳
);
```

与 `meme_manager` 的目录约定：插件把 `<AstrBot 数据目录>/plugin_data/meme_manager/packs/` 也当作可读的图片来源目录。这个目录是否与你的 `meme_manager` 版本一致，取决于对方插件自己的存储布局，未逐一验证。

## 安装

前置：已部署 AstrBot（`>=4.16.0`），已配置一个可用的 aiocqhttp（QQ）适配器，Python 环境有 Pillow。

### 方式一：AstrBot 插件市场

1. 打开 AstrBot 管理后台 → 插件市场。
2. 搜索插件名 `astrbot_plugin_dafeiyu_favorites` 或显示名「表情与话术偏好收藏」。
3. 点击安装，安装完成后到「插件管理」确认插件已启用。
4. 打开插件配置，填写 `owner_qq` 和 `adapter_id`（见下一章），保存。
5. 用主人 QQ 私聊机器人发一句 `/偏好收藏`，能收到「【喜欢的表情包】」开头的列表就说明绑定成功。

### 方式二：后台上传 zip

1. 把本仓库根目录（含 `metadata.yaml` 的那一层，即插件目录本身）打包成 zip。
2. 后台 → 插件管理 → 上传/安装插件，选择这个 zip。
3. 安装完成后确认目录名是 `astrbot_plugin_dafeiyu_favorites`，再填写配置。

> 不同 AstrBot 版本对 zip 内部结构的识别略有差别：最好压缩包根目录直接就是插件文件；如果多包了一层同名文件夹，多数版本也能识别，以你后台的实际提示为准。

### 方式三：手动放到 data/plugins

1. 下载仓库代码（或 `git clone` 到本地）。
2. 把整个目录放到 AstrBot 的 `data/plugins/` 下，目录名保持 `astrbot_plugin_dafeiyu_favorites`。
3. 重启 AstrBot，在插件管理页确认加载成功，然后填写配置。
4. 如果日志出现缺 `PIL` 的报错，执行 `pip install "Pillow>=10.0"`（或 `pip install -r requirements.txt`）。

安装后在后台「插件管理 → 本插件 → 配置」里填写，保存即生效，不需要改代码里的任何常量。

## 配置项详解

配置文件在 AstrBot 后台 → 插件管理 → 本插件 → 配置，字段与仓库里的 `_conf_schema.json` 一一对应。只有下面两项，没有隐藏配置。

| 配置项 | 类型 | 默认值 | 作用 | 注意事项 |
| --- | --- | --- | --- | --- |
| `owner_qq` | string | `""` | 主人 QQ 号，只对这个号的私聊生效 | 填纯数字 QQ 号。留空时插件完全不工作。 |
| `adapter_id` | string | `""` | QQ 平台（aiocqhttp）适配器实例 ID | 必须与 `owner_qq` 一起填；插件按 `adapter_id:FriendMessage:owner_qq` 精确匹配完整会话标识，填错同样完全不工作。 |

补充说明：

- **为什么两项都必须填**：代码里的主人判断是「`owner_qq` 和 `adapter_id` 都非空」才继续，然后比较 `event.unified_msg_origin == f"{adapter_id}:FriendMessage:{owner_qq}"`。所以只填 QQ 号、不填适配器 ID，插件不会响应任何消息。
- **`adapter_id` 是什么**：AstrBot 后台「平台适配器」里这个 aiocqhttp 实例的 ID（有的版本在列表里显示为名称/ID）。它也是会话标识的前缀；在 AstrBot 日志里看到的 `xxx:FriendMessage:123456789` 中，`xxx` 就是它。插件名里不内置任何默认适配器名。
- **怎么确认填对**：填好后用主人 QQ 私聊发 `/偏好收藏`。如果没反应，先核对这两项，再看日志里有没有出现「未识别的消息段」之类的提示；配置错误时插件是完全静默的（不会报错回复）。
- **配置示例**（把值换成你自己的，不要照抄）：

```json
{
  "owner_qq": "123456789",
  "adapter_id": "你的 aiocqhttp 适配器实例 ID"
}
```

- 修改配置不需要重装插件：保存后在插件管理里重载/重新加载一次插件即可生效（不同 AstrBot 版本保存配置后是否自动重载，未验证）。插件的数据目录与配置无关，改配置不会丢收藏。

## 使用方法

默认指令前缀是 `/`；如果你在 AstrBot 里改过通用指令前缀，请按改后的写。除 `/偏好收藏` 外，其余触发词都是自然语言或纯文本，不带前缀。

### 命令

| 命令 / 触发 | 作用 | 说明 |
| --- | --- | --- |
| `/偏好收藏` | 查看收藏列表 | 列出最近 8 张收藏表情（`1. 备注或标签`）和最近 5 条收藏话术（`· 原话前 90 字`）。列表只显示最近这些，更早的收藏仍可用 12 位 ID 取回。 |
| `发收藏图 <1-4 位编号>` | 按编号取回原图 | 编号从 1 开始，1 是最近收藏的一张；编号超出范围会回复「没有这个编号，发 /偏好收藏 看看。」 |
| `发收藏图 <12 位十六进制 ID>` | 按稳定 ID 取回原图 | 大小写不敏感，例如 `发收藏图 0123456789ab`。ID 是收藏时图片 SHA-256 的前 12 位，可在日志或数据库里查到。 |
| `备注 <编号> <描述>` | 给收藏表情起名/改备注 | 也接受 `描述`、`改名` 两个词开头；描述最多 40 字，成功后回复「描述记下了。」 |
| `再发刚才那张` | 重发最近的图 | 只认 180 秒内确认发送过的图。也接受「能不能再发一次刚才那张图」「重发上一张」「再来一遍刚才那张」等变体；引用图片时优先发引用里的那张。 |
| `你发这张我看看` | 把主人刚发的图原样发回 | 也接受「把这张图发给我看看」「这张表情包发一下」等变体。需要消息里带图、引用单张图，或 180 秒内主人发过图且句子里有「这张」。 |
| 「这张我喜欢」「这个视角我喜欢」「好喜欢这张图」 | 收藏图片 | 优先收藏同一消息附带的图；没有附图时用 180 秒内最近的图（主人发的优先，其次机器人发的）。 |
| 「这句我喜欢」「太会说」「说得好」 | 收藏话术 | 收藏被引用的机器人原话，或上一条机器人回复（180 秒内）；只发「我喜欢」、既没附图也没引用图片时不会收藏。 |

### 触发词的实际匹配规则（便于排查）

- **收藏意图**：文本长度 ≤ 60 字；命中正面词（喜欢、好喜欢、好可爱、太可爱、真好看、太好看、好图、太会说、说得好、好会说）；不含否定/条件/反问词（别、不要、不想、不…喜欢、没…喜欢、喜欢吗、你喜欢、讨厌、算了、如果、要是）。
- **指图词**：这张、这个视角、这图、这个图、这张图、这个表情、这张表情、这个角度、好图。
- **指话词**：这句、这段话、这个说法、这种语气、这么说、太会说、说得好、好会说。
- 不满足条件的句子完全不会触发保存，主人正常聊天时不会被插件改写或回复。

### 自动行为

- 主人在私聊里说收藏类句子后，插件在后台保存，不额外发确认消息；本轮对话照常交给模型，模型可能根据注入的「真实收藏结果」自然回一句。
- 主人在私聊触发 LLM 时，插件自动把收藏的语气标签、候选表情列表拼进系统提示词，让模型自己决定要不要发收藏表情。
- 模型如果输出了 `&&偏好图:<编号>&&` 标记，插件会删掉标记；编号在候选里且回复里还没有图时，把对应图片追加到回复末尾。同一回复最多追加一张。
- 消息发出后，插件记录这次回复里的图片和文本，供之后的「再发刚才那张」「这句我喜欢」使用。重启后这段记忆清空。

### 权限边界

- 所有功能只对配置里的 `owner_qq` 生效，且必须是 `aiocqhttp` 平台的私聊；会话标识必须精确匹配。
- 其他 QQ 的私聊、任何群聊：不收藏、不回复、不注入，事件原样交给 AstrBot 和其他插件。
- 直接命令（`/偏好收藏`、`发收藏图`、`备注`、重发等）处理完会 `event.stop_event()`，所以默认对话和其他插件不会再对同一条消息作答；自然语言收藏**不会**停止事件，正常对话不受影响。

## 数据与隐私

- **存储位置**：`<AstrBot 数据目录>/plugin_data/astrbot_plugin_dafeiyu_favorites/`，包括 `favorites.sqlite3` 和 `images/`。全部是本机文件，不经过任何自建服务器。
- **会外发什么**：
  - 图片下载只访问 QQ 的图片 CDN（`gchat.qpic.cn`、`multimedia.nt.qq.com.cn`、`gxh.vip.qq.com`），使用 https，进程内禁用环境代理，不携带 Cookie、账号凭据或本插件自己的密钥（QQ 给的图片地址本身可能带临时参数，属于 QQ 的 CDN 机制）。
  - 收藏内容会进入模型上下文：主人在私聊触发 LLM 时，插件会把语气标签、收藏图片的编号和标签（备注或分类名）拼进系统提示词，随本次对话发给正在使用的模型提供商。这是唯一的「收藏内容外发」路径。
  - 插件本身不主动上传任何数据，也没有统计、遥测、远程配置。
- **谁能看到**：能接触这台机器上 AstrBot 数据目录的人；聊天里只有主人在私聊触发时才会收到插件相关的回复或图片。其他 QQ 用户看不到。
- **保留多久**：没有自动清理，收藏一直保留到手动删除。内存里的「最近一张图 / 最近一句回复 / 最近一条收藏」只在 180 秒内有效，重启即清空。
- **怎么清空**：
  - 清空某张图：停 AstrBot 后，从 `favorites.sqlite3` 删除对应记录，再删 `images/` 下对应文件；或直接用命令管理。
  - 全部清空：停 AstrBot，删除整个 `plugin_data/astrbot_plugin_dafeiyu_favorites/` 目录。
  - 卸载插件通常不会自动删插件数据目录（以 AstrBot 版本行为为准），重装后旧收藏可能还在；想彻底清除请手动删目录。
- **备份**：备份整个插件数据目录即可；`images/` 是普通图片文件，SQLite 可用常规工具打开、导出。
- **日志**：插件日志只写事件类型、异常类型和简短原因（例如下载失败的原因码），不写聊天全文、不写图片 URL（QQ 的 URL 可能带临时签名）。唯一的例外是「未识别的消息段」会打印消息段类型名和组件类名，用于排查适配器兼容性。

## 依赖与前置条件

- **AstrBot**：`>=4.16.0`（见 `metadata.yaml`）。插件使用 `Star`、`StarTools`、`filter` 的 `event_message_type` / `command` / `on_llm_request` / `on_decorating_result` / `after_message_sent` 等 4.x 接口；更老版本未验证。
- **平台适配器**：aiocqhttp（QQ）。代码按平台名 `aiocqhttp` 和 `FriendMessage` 会话结构判断主人私聊；其他适配器未验证。
- **Python 包**：`Pillow>=10.0`（校验图片格式、尺寸、重发前检查）。AstrBot 4.x 运行环境通常已自带；独立环境请 `pip install -r requirements.txt`。
- **可选：`meme_manager` 插件**（第三方，不是本仓库的一部分，不强制安装）。装了以后：插件会把 `plugin_data/meme_manager/packs/` 当作可读取的本机图片来源，并读取事件上的 `meme_manager_delivery_registry` 记录它确认发送过的图。没装时插件所有核心功能照常可用，只是「重发刚才那张」只认本插件自己发过的图。
- **可选：NapCat / OneBot 实现的 `get_image` 接口**。QQ 收藏表情有时只有 file id 没有地址，这时插件调 `get_image` 找回；该接口不可用时表现为「取不到原图」，其他图片不受影响。
- **网络**：能够访问 `gchat.qpic.cn`、`multimedia.nt.qq.com.cn`、`gxh.vip.qq.com`。受限网络（公司代理、严格防火墙）下 QQ 收藏表情的收藏/重发可能失败。
- **权限**：AstrBot 进程需要对插件数据目录有读写权限（SQLite 和图片都要写盘）。

## 常见问题 FAQ

**1. 装好后私聊发 `/偏好收藏` 完全没反应？**

先检查三件事：`owner_qq` 是否填了纯数字 QQ 号；`adapter_id` 是否也填了；是不是在**私聊**里发的。代码要求两项都非空，并且会话标识必须精确等于 `adapter_id:FriendMessage:owner_qq`。配置错时插件是完全静默的。

**2. `adapter_id` 到底填什么？**

到 AstrBot 后台「平台适配器」页面看这个 aiocqhttp 实例的 ID；也可以在 AstrBot 日志里找 `xxx:FriendMessage:你的QQ`，`xxx` 就是它。不要把平台名（如 `aiocqhttp`）当成实例 ID 直接填。不同 AstrBot 版本显示方式不同，以你日志里出现的实际前缀为准。

**3. 说了「这张我喜欢」，但收藏列表里没有？**

收藏判断比较保守，常见原因：

- 句子超过 60 字，或含有「别 / 不要 / 不想 / 算了 / 如果 / 要是 / 你喜欢吗」等词，会被判为不是收藏意图；
- 图片既不在同一消息里，也不在 180 秒内，且没有引用；
- 图片超过 8 MiB、不是 PNG/JPEG/WEBP/GIF，或宽×高超过 2000 万像素；
- QQ 收藏表情下载失败（看日志里有没有 `[偏好收藏] 读取原图失败` / `[偏好收藏] 保存失败`）。

可以换成引用那张图再说「这张我喜欢」，成功率最高。

**4. 说「再发刚才那张」没图？**

「刚才那张」依赖内存里的发送记录，只认 180 秒内、确认发送成功的那张图；AstrBot 重启或隔了几分钟就没了。替代办法：直接引用那张图重发，或先 `发收藏图 <编号>`。

**5. `备注 1 猫猫` 提示「没有这个编号」？**

编号按收藏时间倒序：1 是最近收藏的一张，最多接受 4 位数。先发 `/偏好收藏` 看当前编号；收藏新增后编号会整体后移。用 12 位 ID 取图不受编号移动影响。

**6. 下载 QQ 收藏表情报 403 / 超时 / 网络错误？**

常见于受限网络、公司代理或 QQ CDN 临时拒绝。插件只允许 https 和三个 QQ CDN 域名，会带浏览器 UA 和 QQ 的 Referer，但不会用系统代理。可以稍后重试；不影响普通图片（本地路径 / base64 / 其他方式）的收藏。

**7. 群聊里能用吗？**

不能。插件只处理 `aiocqhttp` 的私聊、且只认配置里的主人 QQ；群聊消息不会收藏、不会触发命令、也不会注入。

**8. `meme_manager` 是必装的吗？**

不是。它只是兼容对象：装了以后「重发刚才那张」能识别 `meme_manager` 发送的表情；没装时所有核心功能照常，只是重发范围只限本插件自己发过的图。

**9. 为什么列表里只有 8 张图、5 条话术？**

`/偏好收藏` 有意只显示最近的一小段，避免回复太长。收藏本身没有上限；更早的图可以用日志/数据库里的 12 位 ID 取回（`发收藏图 <ID>`）。

**10. 模型会不会乱发收藏的图？**

不会乱发：模型只能从当次提供的候选编号里选，且插件会校验编号在候选集合内、回复里还没有图；同一回复最多追加一张。标记写错的会被静默清掉，不会发图。

**11. 数据会跟着插件卸载一起删掉吗？**

通常不会。数据在 `plugin_data/` 下，卸载插件一般不删除该目录（以 AstrBot 版本为准）；想彻底清除请手动删整个插件数据目录。

**12. 收藏的图片和话术会发给第三方吗？**

不会发给插件的作者或自建服务器。只有两种情况会离开本机：图片下载时向 QQ 的 CDN 发起请求；主人在私聊触发 LLM 时，收藏的语气标签、图片标签/编号会随系统提示词发给当前配置的模型提供商。

## 兼容性

- **适配器**：只验证过 aiocqhttp（QQ）私聊。其他平台（Telegram、企业微信等）的会话标识结构不同，未验证是否能绑定；即使能收到消息，`FriendMessage` 格式的精确匹配也可能不成立。
- **AstrBot 版本**：按 4.16.0 及以上的插件接口编写（`Star`、`StarTools`、`filter` 系列装饰器、`on_llm_request`/`on_decorating_result`/`after_message_sent`）。更老版本缺少部分钩子时可能加载失败或功能缺失，未验证。
- **与 `meme_manager` 的关系**：通过两个事件额外数据键对接——读取 `meme_manager_delivery_registry`，写入 `meme_manager_direct_send_attempted`；并读取 `plugin_data/meme_manager/packs/` 目录。这两个键是插件间的约定，不是公开 API，`meme_manager` 不同版本是否一致未验证；对方没装或改键时，最多是「重发刚才那张」少认一些图，不会报错。
- **与其他插件**：直接命令会停止事件传播，避免同一条消息被默认对话或其他插件重复回复；自然语言收藏不停止事件，因此可能与「记忆」「自动回复」类插件同时处理同一条消息。如果别家插件也用 `/偏好收藏`、`备注`、`发收藏图` 这类命令词，可能互相抢占，按需改指令或停用其中一个。
- **指令前缀**：`/偏好收藏` 跟随 AstrBot 的通用指令前缀设置；改前缀后按新前缀发。其余触发词是纯文本匹配，不受前缀影响。
- **图片格式**：只接受 PNG / JPEG / WEBP / GIF；其他格式（如 AVIF、HEIC）会被拒绝并写日志。
- **NapCat 版本**：`get_image` 与 `mface` 原始段的字段格式与 NapCat 版本有关；代码按常见字段处理，旧版本 NapCat 是否能正确取到收藏表情未验证。

## 开发者说明

### 目录结构

```
astrbot_plugin_dafeiyu_favorites/
  main.py            # 插件入口：事件钩子、主人判断、命令、收藏/重发/注入流程
  favorites.py       # 纯逻辑：收藏存储（SQLite）、意图判断、语气标签、路径与 mface 处理
  downloader.py      # 受限图片下载：QQ CDN 白名单、重定向上限、超时与大小限制
  _conf_schema.json  # 后台可视化配置定义
  metadata.yaml      # 插件元信息（AstrBot 市场读取）
  requirements.txt   # 第三方依赖（Pillow）
  README.md
  LICENSE
  .gitignore
```

### 各模块职责

- `main.py`：只做 AstrBot 事件接线。`is_owner()` 统一做主人私聊判断；`handle_feedback()` 处理私聊消息（命令优先、其次收藏意图）；`list_favorites()` 是 `/偏好收藏` 命令；`inject_preferences()` 拼系统提示词；`apply_favorite()` 解析 `&&偏好图:...&&`；`track_delivered()` 记录最近发送的图与文本。
- `favorites.py`：不 import AstrBot，可直接在普通 Python 里测试。包含正则常量、`feedback()` 意图判断、`describe_style()` 语气标签、`Favorites` 存储类（SQLite + 图片目录）、`source_file()`/`local_image()` 路径校验、`sticker_urls()` 与 `segment_types()` 原始消息段解析。
- `downloader.py`：只用标准库 `urllib`。`_validate_url()` 做白名单校验，`_ValidatingRedirect` 保证每一跳重定向都在白名单内，`download_image()` 把网络 I/O 放到线程里，避免阻塞 AstrBot 事件循环。

### 改代码注意点

- 数据路径统一走 `StarTools.get_data_dir(PLUGIN)`，不要写死本机绝对路径；`PLUGIN` 常量必须与目录名、`metadata.yaml` 的 `name` 一致，否则数据目录会变。
- 命令名、触发词正则、`&&偏好图:...&&` 标记格式都在 `favorites.py` 顶部；改任何一个都要同步改 README 和 `_conf_schema.json`/`metadata.yaml` 里的相关描述。
- 「最近一张图 / 最近一句话」都是内存状态，窗口是 180 秒；改窗口时注意「这张」回退逻辑里的时间比较。
- 直接命令处理完要 `event.stop_event()`；自然语言收藏不要 stop，否则会把正常对话截断。
- 图片下载只允许 `downloader.ALLOWED_HOSTS` 里的域名，新增域名要谨慎；不要给下载器加系统代理、Cookie 或账号信息。
- 日志里不要打印聊天全文、图片 URL（可能带临时签名）或任何密钥；异常只打类型和简短原因。
- 图片写入走临时文件加 `os.replace`，配置文件/数据库不要放在插件源码目录里。
